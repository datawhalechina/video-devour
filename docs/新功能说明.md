## 一、ASR 双模式：离线 / 在线自由切换

新增运行时引擎工厂（`backend/devour/asr_factory.py`），语音识别支持两种模式，随时切换、互不影响：

| 模式 | 引擎 | 特点 |
|---|---|---|
| **离线**（默认） | 本地 FunASR Paraformer V2 | 零 API 消耗，带 VAD / 标点 / 说话人分离，支持 Apple GPU 加速 |
| **在线** | DashScope 云端识别（fun-asr-realtime） | 零模型下载、启动即用；本地音频直接流式上传，**无需任何对象存储** |

- 两种引擎输出格式完全一致，处理流水线无感切换
- 重依赖（torch/funasr）改为惰性导入：在线模式下服务秒级启动
- 离线引擎健壮性：
  - 修复自动下载逻辑（不再拉取引擎用不到的 seaco/SenseVoice 模型，约 2GB）
  - **Apple GPU (MPS) 加速**：设备自动选择 CUDA → MPS → CPU，M 系列芯片实测纯 ASR 推理快约 2.2 倍
  - MPS 偶发张量错误自动回退 CPU 重试，保证识别可靠性

## 二、设置控制台（Web 管理界面）

前端新增 `/settings` 页面，无需手改任何配置文件：

- 语音识别模式一键切换（切换到离线时后台自动预加载模型，切到在线时释放显存/内存）
- DashScope / LLM / VLM 的 API Key、接口地址、模型名称在线填写
- 各项配置一键**连通性测试**（真实调用验证，密钥脱敏显示）
- 默认学习阶段设置（小学 / 初中 / 高中）

配套后端能力：

- `GET /api/settings`（密钥脱敏）、`PUT /api/settings`（即时生效）、`POST /api/settings/test`
- 配置持久化到 `settings.json`（已 gitignore），运行时注入 config 模块
- `config.py` 缺失时自动构建默认配置模块，项目开箱即可启动；`config.template.py` 提供手动配置模板

## 三、B站 / YouTube / 微信视频号链接直接处理

将 bilibili-video-download、youtube-downloader 两类下载工具的核心能力移植为项目功能，新增 `/link` 页面：

- **粘贴链接**：自动识别平台，预览窗口内嵌官方播放器（B站 player / YouTube embed）可直接在线播放；直接粘贴 App 分享文案也可以（后端自动提取其中的纯链接）
- **关键词搜索**：B站走官方搜索接口（含 buvid3 cookie 指纹），YouTube 走 ytsearch；结果卡片含封面、时长、UP主
- **一键下载处理**：yt-dlp 下载（自动合成 mp4、下载进度可视）→ 自动接续标准处理流水线
- 稳定性：B站 412 风控自动退避重试；YouTube bot 检查时元数据回退 oEmbed，下载支持 `YTDLP_COOKIES_FILE` 环境变量挂载浏览器 cookies
- **微信视频号渠道**（新增）：支持 `weixin.qq.com/sph/...` 分享链接，解析服务换直链下载后接续流水线，详见下文
- 新增 API：`POST /api/video/link/info`、`/api/video/link/search`、`/api/video/link`
- 任务状态新增「下载视频」阶段（0-15% 实时进度）

### 微信视频号下载渠道

参考 [joeseesun/qiaomu-wx-video](https://github.com/joeseesun/qiaomu-wx-video) 与 [ltaoo/wx_channels_download](https://github.com/ltaoo/wx_channels_download) 的 sph worker 源码实现。视频号没有公开直链，按优先级走三条链路：

1. **直连解析（推荐，无第三方）**：设置页填入腾讯元宝 Cookie 后，后端复刻 sph worker 的解析链——
   调用元宝 `get_parse_result` 换取 exportId + token → 调视频号 `finder-preview get_feed_info` 取媒体列表
   （`mediaUrl + urlToken`）→ 若媒体带 `decodeKey`，用 ISAAC64 密钥流解密前 128KB
   （WechatSphDecrypt 算法的 Python 移植，已与独立参考实现交叉验证）→ ffprobe 校验落盘
2. **自建解析服务**：设置页/环境变量 `WECHAT_RESOLVER_URL`（可选 Token，Bearer 鉴权），
   兼容 JSON 直链、sph worker feed 结构、HTML 与直接回流媒体四类响应，多候选源降级
3. **本地捕获（引导用户手动）**：wx_channels_download 依赖微信桌面端登录态 + 根证书 + 本地代理，
   属重量级人工流程且涉及系统安全设置，项目不自动执行；失败报错中引导用户走该路径后在「上传视频」页上传

约束与配置：
- 设置页新增「微信视频号」卡片：元宝 Cookie（脱敏存储于 settings.json）、自建解析 URL/Token
- 环境变量等价物：`YUANBAO_COOKIE`、`WECHAT_RESOLVER_URL`、`WECHAT_RESOLVER_TOKEN`
- 分享链接可能过期、直播回放无法解析、元宝 Cookie 会过期（401 时提示更新），此类情况均返回明确的中文引导
- 视频号不支持关键词搜索，只能粘贴分享链接；WebUI 预览窗口对视频号显示说明卡片（微信页面禁止内嵌）
- 配置 Cookie 后 `probe` 会返回真实标题/作者/封面；未配置时展示占位信息

## 四、学习阶段（小学 / 初中 / 高中）

上传视频或处理链接时可选学习阶段，贯穿大纲与报告的全部 prompt：

- LLM 按阶段调整语言深度（小学→通俗易懂、高中→可含专业术语）
- 实测同一视频，小学阶段报告语气明显更简单亲切

## 五、学习卡片与 Markdown 导出

报告页新增两个按钮：

- **生成学习卡片**：LLM 将报告转换为手机尺寸（393px）Bento Grid 风格 HTML 卡片，新窗口预览，结果缓存
- **导出 Markdown**：大纲 + 精简报告合并为单个 `.md` 下载，**本地图片内嵌 base64**，单文件在任何 Markdown 查看器中直接显示图片，不依赖服务器

## 六、LLM 输出质量增强

- **强制简体中文输出**：无论视频原语言是什么（如英文课程），大纲、报告、学习卡片一律输出中文，专有名词保留原文
- **限流自动重试**：对限流/超时类错误指数退避 + 随机抖动重试（最多 5 次），并正确区分可重试与不可重试错误
- **禁止编造图片**：报告后处理强制剥离外链占位图（如 example.com），确保只引用真实存在的关键帧

## 七、关键帧链路修复与兜底

- 大纲只有一级标题（无二级章节）时，自动兜底切分整段视频，保证抽帧 / 关键帧环节继续可用
- VLM 选帧找不到标题专属帧目录时，回退使用唯一可用帧目录
- 报告/大纲图片显示链路修复：静态资源代理、相对路径解析、错误处理重写

## 八、开发与部署体验

- `config.template.py` 配置模板入库，真实 `config.py` 维持 gitignore
- Vite 代理补齐 `/static`，开发模式下报告图片正常显示
- 清理误提交的 `__pycache__` 产物并加入 gitignore
- 依赖新增：`dashscope`、`openai`、`yt-dlp`、`requests`

## 九、Agent Skill（跨 agent 通用）

核心能力提炼为遵循 `.agents/skills` 开放约定的技能，任何支持的 agent（Codex / Claude Code / Cursor 等）
在仓库内即可直接调用，无需 Web 界面：

```
.agents/skills/videodevour/
├── SKILL.md           # 触发条件、前置检查、工作流
└── scripts/devour.py  # 入口：search / info / process / report
```

```bash
# 一键把视频处理成中文图文报告
python3 .agents/skills/videodevour/scripts/devour.py process "https://www.bilibili.com/video/BV..." --level 高中
```

脚本自动切换到项目 `.venv` 运行；项目根目录按 `--home` → `VIDEO_DEVOUR_HOME` → 脚本所在仓库 →
默认路径 的顺序解析。本机使用可软链到 `~/.agents/skills/`。

## 快速上手（本次更新后）

```bash
# 后端（首次 uv sync 安装依赖；离线模式首次会自动下载模型或手动放置到 models/iic/）
./start_backend.sh

# 前端
cd frontend && npm install && npm run dev
```

打开 http://localhost:3000 ：

1. **控制台**（`/settings`）：选模式、填 Key、点连通性测试
