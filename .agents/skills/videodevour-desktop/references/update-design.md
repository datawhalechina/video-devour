# 热更新设计（组件更新 + 更新弹窗）

> 状态：**设计，未实现**。本文是可执行的落地方案，不是已实现能力的描述。
> 与 `planning/桌面客户端化方案.md` 第 5.2 节、阶段 E3 对应（当时判断"适配器与兼容更新验证后再开放热更"，该前置条件依然成立）。

## 0. 核心约束（决定一切）

**macOS 上任何对 `.app` 内部的修改都会让代码签名失效** → 用户看到"已损坏"（见 pitfalls E1）。
因此热更新内容**必须放在 bundle 之外**，即已有的用户数据目录：

| 平台 | 数据目录 |
|------|---------|
| macOS | `~/Library/Application Support/VideoDevour/` |
| Windows | `%LOCALAPPDATA%\VideoDevour\` |

**不要自动拉取仓库源码运行**，三个理由：

1. **源码 ≠ 可运行产物**：前端需 `npm run build`（用户机器无 Node）、Python 依赖需安装，冻结包里跑不了 repo checkout
2. **没有原子性和版本边界**：`main` 随时在动，客户端会拿到半新半旧的混合状态，bug 无法复现
3. **安全上是单点风险**：让所有客户端自动执行公共仓库 HEAD 的代码 = 仓库一旦被投毒就是全量 RCE

**正确模型：只消费签名过的构建产物，永不消费源码。**

## 1. 三层可行性

| 层 | 内容 | 可行性 | 说明 |
|----|------|--------|------|
| **前端** | React 构建产物（HTML/JS/CSS） | ✅ 最容易，收益直接 | 后端改动 5-10 行 |
| **纯 Python 后端逻辑** | 解析、提示词、字幕处理 | ⚠️ 有边界 | 需覆盖机制；**不能换原生扩展** |
| **依赖与原生代码** | 三方包、`.so`/`.dylib`、壳本身 | ❌ | 只能整包更新 |

### ⚠️ 未验证的技术前提（实现前必须实测）

后端补丁依赖"把用户数据目录插进 `sys.path` 以覆盖已冻结模块"。但 PyInstaller 会把冻结导入器挂到 `sys.meta_path`，**对已打进 PYZ 归档的模块，`sys.path` 插入未必能遮蔽它**。

- **必须先写最小实验验证**，再决定后端热更是否可行
- 若无法覆盖：退而求其次——只热更"未被静态导入的模块"（如 yt-dlp 适配器），或改用子进程方式（见 §4）

## 2. 更新源：版本清单 + 签名产物

发版时在 GitHub Releases 上传一份 `latest.json`：

```json
{
  "app": { "latest": "0.1.7", "min_supported": "0.1.4" },
  "components": [
    {
      "name": "frontend",
      "version": "2026.09.16",
      "url": "https://github.com/.../releases/download/v0.1.7/frontend-dist.zip",
      "sha256": "…",
      "min_app": "0.1.6"
    },
    { "name": "yt-dlp", "version": "2026.09.16", "url": "…", "sha256": "…", "min_app": "0.1.6" }
  ]
}
```

客户端流程：

1. 启动后**延迟几秒**拉清单（不阻塞启动）→ 比对本地版本
2. 有新组件 → 下载到临时目录 → **校验 SHA256** → 原子换入数据目录
3. 进一步安全（推荐）：清单用 **ed25519 签名**，公钥内嵌在 App 内，防中间人投毒
4. 保留上一版本目录 + 提供 `--safe-mode` 跳过所有补丁，作为回滚兜底

### 网络注意（主战场在国内）

- 用 Releases 的**静态资产 URL**，**不要用 GitHub API**（未认证 60 次/小时限流，用户多了必踩）
- 检查失败**静默**（只写日志），绝不因拉不到清单弹错误
- 节流：启动后延迟 + 每 N 小时一次 + 结果缓存
- 设置页提供「自动检查更新」开关 + 可自定义清单地址（符合项目 local-first 调性）

## 3. 更新弹窗：前端渲染，壳执行

### 分工原因

| 职责 | 归属 | 原因 |
|------|------|------|
| 拉清单、下载、校验、替换 | `desktop/shell.py` | 只有壳管进程生命周期、能写 bundle 外文件、能重启应用 |
| 展示弹窗、进度、更新说明 | `frontend` | 复用现有设计系统；原生对话框（NSAlert/MessageBox）样式割裂 |
| 实际落位 | `desktop/shell.py` | 前端跑在后端进程里，更新时会被杀掉 |

### 接口

沿用现有 `captureLogin` 的 js_api 模式，`Bridge` 加三个方法：

```python
check_update() -> {"available": bool, "current": str, "latest": str,
                   "notes": str, "size": int, "kind": "frontend|component|app"}
start_update() -> None          # 后台线程下载，立即返回
update_progress() -> {"phase": str, "percent": int, "error": str|None}
```

`frontend/src/api/desktopBridge.js` 加包装（浏览器模式下自动降级隐藏，同 `isDesktopClient()` 现有做法）；
`AppShell.jsx` 挂载时调一次 `check_update()`。

进度用**前端 500ms 轮询**，不要让壳主动 `evaluate_js` push（注入有失败风险），与项目里任务进度的轮询模式一致。

### 交互：两段式，不要一上来就弹模态

```
后台静默下载 → 侧边栏小圆点
   ↓ 下载+校验完成
弹「已就绪，重启生效」+「立即重启 / 稍后」
```

一检测到就弹模态会打断正在看报告/跑任务的用户。Chrome、VS Code 都是这个模式。

按类型区分行为：

| 类型 | 提示方式 | 生效方式 |
|------|---------|---------|
| 前端 | 横幅 | 刷新窗口即可，**不用重启** |
| 组件（yt-dlp 等） | 横幅 | 下个任务生效 |
| 整包 | 模态 + 重启按钮 | 需重启（受 §5 约束） |

## 4. 优先做 yt-dlp（P0）

**理由**：平台反爬一改（B站/YouTube 频繁），所有旧客户端直接失效——这是最值得热更、也最痛的组件。它纯 Python、体积小、迭代快。

**做法**（关键：绕开 §1 的覆盖不确定性问题）：

1. 把 `backend/devour/video_downloader.py` 的 Python API 调用抽象成**统一下载适配器**
2. 适配器**以子进程方式调用 yt-dlp 可执行文件**（而非 `from yt_dlp import YoutubeDL`）
3. 更新 = 换一个二进制到数据目录，与冻结导入器无关

**组件包必须包含**：yt-dlp 可执行文件 + **EJS**（YouTube n challenge 求解脚本）+ **JS runtime（Deno）**——三者版本需配套，整包替换，不能只换一个 exe。

> 注意：`_get_ydl` 目前还承担 UA/Referer 指纹、B站退避重试、`ffmpeg_location` 等逻辑，迁移到子进程时要一并保留。

## 5. 三个必须处理的边界

### 5.1 任务运行中绝不自动重启

视频管线跑几分钟，中途重启等于白跑。

- 重启前先查后端 `processing_tasks`，有任务则把「立即重启」置灰
- 文案改为「任务完成后生效」

### 5.2 整包更新的签名死结

- **签名证书到位之前，整包更新弹窗不要做**——用户点「更新」→ 又弹「已损坏」，比不更新更糟
- 替换必须**整套换**（新的 `.app` / `VideoDevour\` 目录），不能只换 exe
- macOS：运行时无法安全自我覆盖，需下载到临时目录 → 由壳写小脚本等自己退出后 `ditto` 替换 → 重新拉起
- Windows：运行中的 `.exe` 不能覆盖但可改名，标准做法「重命名旧的 → 写新的 → 重启」

### 5.3 前端热更的安全阀（必须同批实现）

**一旦推了坏的前端包，用户就是白屏，连"回滚"按钮都点不到。**

壳需在启动时检测：连续 N 次前端加载失败 → 自动回退到 bundle 内置版本，并记录日志。

> 这条不能事后补，必须与前端热更在**同一批次**实现。

## 7. 验证要点

- 断网/清单 404/下载中断/校验失败 → 全部静默降级，不弹错误、不影响正常使用
- 下载中途断电 → 重启后不残留半成品（临时目录 + 原子替换）
- 坏包注入：故意推一个加载失败的前端版本 → 验证安全阀自动回退
- 任务运行中收到更新 → 验证「立即重启」被禁用
- 回滚：`--safe-mode` 启动应跳过所有补丁，且能正常打开
