## 2. 产物结构

```
desktop/dist/VideoDevour.app/                 # 367MB
└── Contents/
    ├── Info.plist
    ├── MacOS/VideoDevour                     # 启动脚本（exec Resources/VideoDevour）
    └── Resources/                            # PyInstaller onedir 产物
        ├── VideoDevour                       # 单可执行文件，双角色
        ├── _internal/
        │   ├── bin/ffmpeg, ffprobe           # 86MB（arm64 静态构建）
        │   ├── frontend/dist/                # 4.4MB 前端产物
        │   ├── camel/ tiktoken_ext/ yt_dlp/  # 运行时依赖
        │   └── ...
```

### 单可执行文件双角色设计

```
VideoDevour                  → 桌面壳：派生自身 --backend-only + 开窗口
VideoDevour --backend-only   → 后端：uvicorn 托管 API + 前端
```

原因：.app 内查找第二个 EXE 会引入路径与签名复杂度；`sys.executable` 派生自身最稳。

## 4. 打包过程中发现并修复的坑（重要）

| # | 问题 | 现象 | 修复 |
|---|------|------|------|
| 1 | `console=False` 导致静默退出 | macOS 窗口模式用 `runw` 引导器，不保留标准文件描述符，uvicorn 启动后无任何日志即退出 | spec 改 `console=True`；Windows 侧由壳传 `CREATE_NO_WINDOW` 隐藏控制台 |
| 2 | stdout 握手在窗口模式不可用 | 壳读不到端口 | 改为握手**文件**（原子替换写入）+ stdout 双通道 |
| 3 | `tiktoken_ext` 未收集 | 任务在 LLM 调用处报 `Unknown encoding o200k_base`，任务失败 | spec 用 `find_spec` 定位命名空间包目录并作为 datas 收集（`collect_data_files` 无效） |
| 4 | `camel.runtimes` 收集告警 | 缺 tqdm（仅 Docker runtime 用） | 加入 `requirements-lite.txt` |
| 5 | 关闭壳后后端成孤儿 | 残留进程继续占用端口 | 壳装信号处理器 + **后端监测父进程**（壳被 SIGKILL 时也能退出） |
| 6 | 端口竞争 | 方案明确禁止"探测→关闭→再绑定" | 绑定 socket 后直接交给 `uvicorn.Server.run(sockets=[sock])` |

### 4.1 真机测试暴露的缺陷（2026-09-09 补充）

macOS 测试包首次实测时报告 `ffmpeg is not installed`，定位出 4 个真实缺陷：

| # | 问题 | 现象 | 修复 |
|---|------|------|------|
| 7 | `_get_ydl` 未设 `ffmpeg_location` | yt-dlp 合并音视频时只查系统 PATH，**忽略捆绑的 ffmpeg**，报 `You have requested merging of multiple formats but ffmpeg is not installed` | `_get_ydl` 传入 `ffmpeg_location=ffmpeg_path()`；yt-dlp 会据此自动推导 ffprobe（含 Windows `.exe`）。已用真实 B站链接验证合并成功 |
| 8 | 父进程监测误杀独立启动 | 后台启动后端时 shell 立刻退出，`os.getppid()` 变化触发"父进程已退出"而自行终止 | 改为壳通过 `--parent-pid` **显式传入 PID** 才启用监测；独立启动/CI 不监测 |
| 9 | 轻量包默认离线 ASR | 新用户无 `settings.json` 时默认 `offline`，但包内无 torch，一上传视频必然失败 | `DEFAULT_SETTINGS.asr_mode` 改为 `online`（方案 3.1 要求）；已有配置不被静默改写 |
| 10 | 离线模式裸异常 | 报 `No module named 'torch'`，用户无法据此操作 | `asr_factory` 捕获 ImportError 并提示"切换在线 ASR 或安装增强版" |
| 11 | provider/model 串台 | 切换在线 ASR 提供商后残留旧模型名，报 `Model not found` | 新增 `PROVIDER_DEFAULT_ASR_MODEL` 常量；切 provider 且未显式指定模型时自动跟随 |

**验证**：修复后 macOS 冻结包在 PATH 限制为 `/usr/bin:/bin`（无 ffmpeg）下，完整跑通
B站链接 → 下载合并 → 在线 ASR → 关键帧 → 报告（产物含 26 张关键帧，状态 completed）。

## 5. 已实现的能力（对照方案条款）

- **4.2 启动与同源**：绑定 `127.0.0.1:0` 由 OS 分配端口，握手文件报告实际端口；前端由同一 FastAPI 托管；API/资源路由优先，SPA fallback 最后注册；未注册 `/api` 与缺失资源返回 404。
- **4.1 路径**：新增 `backend/runtime/paths.py`，`data_root` 优先级 `--data-dir` → `VIDEO_DEVOUR_DATA_DIR` → 平台默认目录 → 源码根（开发模式行为不变）。settings/tasks/uploads/output/subtitle_notes/document_library 已全部接入。
- **5.2 下载器**：ffmpeg/ffprobe 统一解析（环境变量 → 捆绑 `bin/` → PATH），已覆盖 ASR 音频提取、视频切片、抽帧、视频号校验。
- **6.2 桌面行为**：单实例文件锁、退出时回收进程树、原生文件选择/另存为/打开目录桥接。

## 7. 复现方式

```bash
# 1. 轻量依赖
uv venv .venv-lite --python 3.12
uv pip install --python .venv-lite/bin/python -r requirements-lite.txt pyinstaller pywebview

# 2. 捆绑二进制（静态构建）
./desktop/fetch_binaries.sh

# 3. 前端
cd frontend && npm run build && cd ..

# 4. 构建 .app
PYTHON=.venv-lite/bin/python ./desktop/build_mac.sh --sign

# 5. 运行
open desktop/dist/VideoDevour.app
# 内测被 Gatekeeper 拦截时：xattr -cr desktop/dist/VideoDevour.app
```

Windows：`desktop/build_win.ps1`（详见脚本头注释）。
