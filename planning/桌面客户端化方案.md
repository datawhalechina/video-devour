## 1. 优化方向：围绕第一份笔记和长期使用体验

VideoDevour 的核心价值是将视频转为可阅读、可编辑、可检索、可导出的学习资料。当前已有字幕速记、完整图文报告、学习卡片、思维导图、知识图谱和个人文档库。桌面客户端应把这些能力组织成可靠的本地工作流程。

本轮优先级确定为：**首次使用可理解 → 轻量链路可运行 → 长任务可控制 → 资料不丢失 → 安装与升级可靠 → 本地模型增强**。

| 决策项 | 修订后的方向 | 依据与边界 |
|---|---|---|
| 产品入口 | 新建任务、任务列表、文档库、设置构成桌面工作区 | 复用现有页面；桌面启动优先恢复工作区，介绍型首页保留给 Web |
| 处理方式 | 并列提供「字幕速记」「图文报告」 | 前者读取平台字幕并调用 LLM；后者保留语音、画面与章节关联，不因追求速度自动降级 |
| 首发形态 | 先验证不含本地 ML 依赖的轻量包 | 支持字幕速记和在线 ASR 图文报告；配置由用户提供，未配置时仍能打开已有资料 |
| 本地能力 | 本地 ASR 与本地语义匹配作为后续增强 | 模型与 Python 原生依赖是两类资源，下载模型不能让轻量冻结包自动具备 torch |
| 架构 | 桌面壳 + 本地 FastAPI + 受控任务执行器 | 复用算法能力；需要整理配置、任务、路径边界，不能按“后端原样复用”估算 |
| 桌面壳 | pywebview 先做限时验证，通过后可继续用于首发 | 不预设第二期必须换壳；只有发布、交互兼容或维护成本验证不通过才比较 Tauri 2 / Electron |
| 后端打包 | PyInstaller onedir 为首选验证路线 | 壳的打包与后端打包分别验证；第一批实验就覆盖两种目标系统 |
| 更新 | 首发采用可重复安装的版本升级，独立组件热更后置 | 先解决保留数据和迁移兼容，再实现下载器更新与整包自动更新 |
| 排期 | 以阶段出口与证据推进 | 原“阶段 0 一周 + 阶段 1 一周”和包体积属于未验证估算，不作为承诺 |

**本地 ASR 不等于整条流水线离线可用。** 当前报告生成仍使用 LLM/VLM 服务，部分可视化还依赖 CDN。客户端必须分别说明“本地转写”“联网生成”“离线阅读”，不把 Full 版命名或宣传为完全离线版。

## 2. 原方案审查：已实现、遗漏与需要修正的假设

以下是静态代码审查结果，未执行真实视频处理、跨平台安装或性能基准。

| 发现 | 当前代码证据 | 对优化思路的影响 |
|---|---|---|
| API 相对路径已经完成 | `frontend/src/api/videoService.js`、`settingsService.js` 使用 `/api`；编辑页也使用相对 `fetch` | 改成“复用并统一客户端”，无需重复安排从固定 URL 迁移 |
| Vite 配置端口为 3000 | `frontend/vite.config.js` 已代理 `/api`、`/static` 到 8000 | 保留开发代理；不能按全部跑在 5173 的假设改造 |
| 后端已有健康检查 | `backend/api/main.py::health_check` 对应 `/api/health` | 扩展已有接口；不另造含义重叠的 `/health` |
| 静态托管尚不完整 | 根路由返回 API 信息；`StaticFiles` 在创建 `OUTPUT_DIR` 之前挂载 | 首次空目录启动可能失败；先建目录，再挂载，SPA fallback 放在 API 和资源路由之后 |
| 离线 ASR 工厂已惰性导入，但启动仍有重依赖 | `asr_factory.py` 已分支导入；`startup_event` 默认预加载离线模型；`pipeline.py` 顶层导入 `text_similarity_matcher.py`，后者尝试导入 sentence-transformers | 不能只改 ASR 工厂；轻量模式须隔离整条 import 链并取消首启强制模型加载 |
| 在线 ASR 不会自动去掉本地匹配模型 | `pipeline.py::_generate_and_match_outline` 固定 `use_semantic=True` | 显式配置匹配策略；现有字符串匹配可作为验证基线，但必须检验章节、截图对应质量 |
| 已有无需视频下载和 ASR 的入口 | `POST /api/video/link/notes`、`backend/devour/subtitles.py`、`LinkProcess.jsx` | 字幕速记进入首发范围，不应等到后期 Lite 版再考虑 |
| 字幕速记尚未进入统一任务与文档体系 | 当前接口等待生成完成才返回；文件在 `output/subtitle_notes/`；`library_search` 只扫描 `frames_*` 下的三类报告 | 字幕任务也要可排队、查看结果和检索；处理字幕超长截断时要明确展示覆盖范围 |
| 进度阶段是按时间模拟的 | `run_pipeline_with_progress` 每两秒递增预设阶段；另有 `algorithm/timing.py` 真实耗时记录 | 接入流水线阶段事件，复用计时能力，不将 95% 长时间等待当作真实进度 |
| 取消没有贯通实际执行链 | `delete_task` 取消 asyncio task；实际 pipeline 在 ThreadPoolExecutor 中执行 | 取消协程不等于停止线程和 FFmpeg；取消与删除必须分开设计 |
| 多任务共享可变状态 | `processing_tasks` + 直接重写 `tasks.json`；全局 `asr_engine` / config；`pipeline._setup_environment` 替换根 logger handlers | 首发全局限制一个重任务，逐步隔离任务参数、日志与 worker，不先增加并发 |
| 上传整文件读入内存 | `upload_video` 中 `content = await file.read()` 后一次写盘 | Web 上传改分块；桌面本地文件通过原生选择与受控路径导入，避免重复复制大视频 |
| 运行目录不只在 API 里 | `settings_store`、`subtitles`、ASR 引擎、模型管理器、pipeline 输出与日志都有根路径依赖 | 新建共享运行时路径模块，区分资源、用户数据、缓存和用户原视频 |
| `--home` 的原有含义有兼容风险 | `.agents/skills/videodevour/scripts/devour.py::project_home` 要求该目录包含 `backend`，还依赖 `.venv/bin/python` | 它代表源码根，不是数据根；原方案把该逻辑定位到 `asr_factory.py` 不准确，不能直接改变环境变量含义 |
| 下载环境不仅需要 FFmpeg | `video_downloader.py::_youtube_js_runtime`、字幕路径使用 JS runtime；现有设置页已有下载环境自检 | 构建清单加入经过验证的 JS runtime 与 EJS；复用现有诊断界面 |
| yt-dlp 当前通过 Python API 调用 | `video_downloader.py` 中 `YoutubeDL` | 下载一个新 exe 不会替换冻结包内的模块；独立更新前先抽象统一下载适配器 |
| 编辑与预览需要桌面专项验证 | `EditorPage.jsx` 手动保存后整页跳转；`api/aiService.js` 返回模拟文本；`ReportViewer.jsx` 预览 iframe 未设 sandbox | 优先补保存状态、草稿恢复和退出保护；模拟 AI 能力接入前隐藏或明确标注 |
| 现有资料并非全部可离线查看 | `report_viz.py` 引用 CDN 上的 ECharts / markmap | 离线阅读需要内置渲染资源，同时隔离生成 HTML 的脚本权限 |
| 模型清单存在差异 | `modelscope_manager.py` 列出 seaco Paraformer / SenseVoice；实际 V2 引擎检查另一组 Paraformer 路径 | 模型管理按实际启用引擎生成清单，不能把现有列表和体积直接当作发行基线 |

## 3. 用户流程与首发范围

### 3.1 首次打开

1. 先显示工作区与现有文档，不触发大模型下载；状态区明确服务是否就绪。
2. 用户选择任务方式后，只检查该方式的必需条件：字幕速记检查 LLM 和字幕访问；图文报告再检查 ASR、FFmpeg 与 VLM。
3. 设置页提供当前能力状态与修复入口。已有“连通性测试”“浏览器 Cookie 导入”“下载环境自检”继续复用，不强制用户填写所有供应商。
4. 新安装默认推荐在线 ASR；已有用户的离线设置保留。轻量包遇到离线配置时说明缺少本地引擎，提供配置在线模式或安装增强版的入口，不静默改写设置。

### 3.2 从输入到结果

| 场景 | 行为 | 失败或限制时的处理 |
|---|---|---|
| 想快速整理 B站 / YouTube 内容 | 选择字幕速记，展示字幕语言、来源与覆盖范围 | 无字幕或访问失败时说明原因，由用户选择图文报告；不自动启动有额外成本的流程 |
| 需要课程画面、章节和截图 | 选择图文报告，保留现有完整流水线 | 明确失败阶段，可用产物先呈现；后续按有效检查点重试 |
| 处理本地大视频 | 原生选文件或拖入，默认引用原文件，可选复制到工作区 | 原文件移动后可重新定位；删除任务不能删除引用的原文件 |
| 继续上次工作 | 从任务列表或文档库恢复，重新连接后端状态 | 服务断开显示重连状态，不立即把处理任务判定为失败 |
| 阅读与编辑 | 统一文档入口、自动草稿、显式保存状态、Markdown 导出 | 图片与相对路径可移植；离开页面或退出前处理未保存内容 |

学习卡片、思维导图和知识图谱继续按需生成，默认不勾选。报告完成即可阅读，附加产物作为独立任务显示，不让它们的失败覆盖已成功的报告。

首发不增加账户系统、云同步、团队协作、商业化、多模型商店或新的知识问答系统。优先把现有功能串成稳定闭环。

## 4. 目标架构与关键契约

```text
桌面壳（窗口、原生文件选择、保存、单实例、退出协调）
  ├─ 读取启动握手，加载 http://127.0.0.1:<实际端口>/
  └─ 管理本地服务进程
       ├─ FastAPI：React 静态产物 + /api + 受控媒体/文档访问
       ├─ 任务服务：状态持久化、队列、参数快照、产物索引
       └─ 受控 worker（首发最多一个重任务）
            ├─ 字幕 → LLM → 速记
            └─ 下载/本地文件 → ASR → 章节匹配 → 关键帧 → 报告
                 └─ FFmpeg / FFprobe / yt-dlp / JS runtime
```

### 4.1 资源与数据路径

建议新增 `backend/runtime/paths.py`，供 API、算法、下载器和 CLI 共用；不要把共享运行时放进仅服务某条算法的目录。

| 路径概念 | 内容与约定 |
|---|---|
| `resource_root` | 安装包内只读资源：前端 dist、捆绑二进制、默认配置模板；不从当前工作目录推导 |
| `data_root` | 设置、任务数据库、持久文档、应用管理的输入文件、运行日志 |
| `cache_root` | 可重新生成的转码、抽帧、临时文件；用户清理时不影响已引用到报告的图片 |
| `model_root` | 按引擎和版本管理的模型缓存；重定向 ModelScope 与 Hugging Face / sentence-transformers 的实际缓存写入 |
| `source_path` | 用户选择的外部原文件；记录“引用/应用副本”归属，不纳入默认清理 |

数据根优先级建议为新参数 `--data-dir` → `VIDEO_DEVOUR_DATA_DIR` → 平台默认目录。桌面 macOS 默认 `~/Library/Application Support/VideoDevour`，Windows 默认 `%LOCALAPPDATA%/VideoDevour`，大量视频和模型不放入漫游配置目录。缓存、模型位置允许独立设置。

开发模式未指定目录时继续使用源码根。现有 CLI 的 `--home` / `VIDEO_DEVOUR_HOME` 暂保留源码定位语义，新增数据目录参数；以后弃用必须单独公告并提供兼容期。不要通过全局 `chdir` 解决打包后的路径问题。

迁移采用显式选择旧目录、复制、校验、记录版本的方式；不扫描用户整盘，不覆盖新目录配置，不自动删除旧数据。旧 `tasks.json` 的绝对路径和历史 `frames_*` 目录都需要迁移映射，不能只搬 settings 文件。

### 4.2 启动、同源与本地访问

- 由后端绑定 `127.0.0.1:0` 并通过父子进程管道报告实际端口、进程身份和协议版本；不要先找空端口、关闭 socket 再启动，避免竞争。
- 扩展现有 `/api/health`：区分服务就绪与各能力状态，例如 `unconfigured / available / loading / error`。健康检查不下载模型、不调用付费服务，服务可用不以 ASR 已加载为条件。
- 前端资源由同一个 FastAPI 实例托管。API 和资源路由优先；前端已知路由刷新返回 `index.html`，未知 `/api`、缺失 JS/CSS 和媒体文件仍应返回 404。
- 抽取统一 API 客户端，覆盖现有两个 axios 实例和分散的 `fetch`；保留错误码、HTTP 状态和重试建议，避免依靠错误字符串识别 404。
- 桌面 API 使用每次启动的随机会话凭据和 Host/Origin 校验。凭据通过受控握手传递，不写日志、URL或可公开获取的静态文件。仅监听回环地址或配置 CORS 都不等于鉴权；pywebview 官方也建议 REST API 使用会话 token 防护。[官方说明](https://pywebview.flowrl.com/guide/security)
- 原生桥只允许文件选择、保存、打开已授权文件和窗口操作，不向页面暴露任意 shell 执行或任意路径读取。
- 会话需覆盖图片、视频、下载等无法统一添加请求头的访问，可由受控引导建立 HttpOnly 会话 Cookie，并为写操作校验 CSRF token；Cookie 不按端口隔离，凭据与实例校验不能省略。最终方案在桌面验证阶段确定。
- 生成 HTML 在受限 iframe 中展示，禁用同源权限与原生桥；所需本地脚本资源单独提供受限读取方式。外链交给系统浏览器，不在有原生权限的主页面载入任意网站。
- 动态端口会改变 Web origin，现有 localStorage 任务恢复不能作为持久化依据。任务、草稿和最近文档写入后端；主题等偏好也通过稳定存储恢复。

### 4.3 任务执行与数据可靠性

首先限制重任务并发为 1，让不同提交进入队列。保留媒体步骤的有限内部并发，但让 ASR、FFmpeg 和云端请求共享可配置的资源预算。参数在提交时快照化，运行中修改设置只影响后续任务；密钥用受控引用读取，不复制到任务导出或日志。

建议状态模型为 `queued → running → completed / failed / cancelled / interrupted`，另设 `cancelling` 过渡态。具体 `stage`、开始时间、最后事件时间、错误原因和产物记录独立于状态保存。

- 持久化优先采用 SQLite，由任务服务负责写入；大文件继续落盘。迁移旧 JSON 时保留 task_id、来源链接、学习阶段与输出映射，失败可回到旧数据副本。
- worker 放到可终止的独立进程，由任务服务收集真实阶段事件；任务服务是状态唯一写入方。每任务日志与输出目录绑定 task_id，不再替换全局根 logger。
- FFmpeg、下载器等子进程归属 worker 管理。取消先发协作信号，超时再终止进程树，确认退出后才提交 cancelled 状态或允许清理文件。Windows Job Object / macOS 进程组及父进程异常退出的清理机制都要验证。
- 删除是独立动作，只清理应用拥有的文件；正在执行的任务先取消并等到退出。不能在仍写文件时直接删目录。
- 首发先做到中断可识别、产物可保留、可以重试；不承诺任意步骤断点续跑。下一阶段为 ASR、大纲、报告等边界记录输入指纹、参数/模型版本和完整产物，校验一致才复用，避免重复调用已完成的付费步骤。
- 实际阶段事件替换模拟进度；能计数的显示已完成/总量，不能计数的显示阶段与耗时。先保留 2 秒轮询并加入不重叠、终态停止和断线退避；SSE 仅在实测需要时再加。

冻结后 `sys.executable` 指向应用可执行文件，不能把它当成普通 Python 去执行 `-m pip` 或任意脚本。worker 使用显式入口协议；如采用 multiprocessing，在入口处理 `freeze_support()` 并验证没有递归启动窗口。[PyInstaller 官方说明](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html)

## 5. 轻量化与性能优化

### 5.1 先拆依赖，再测包体积

建立可重复构建的依赖集合：基础 API/任务服务、在线报告所需组件、可选本地 ASR、可选语义匹配、桌面壳。锁定构建版本并验证传递依赖，不能在同一个装满所有依赖的开发环境里打“Lite”包。

- `torch / funasr / modelscope / sentence-transformers` 移到可选集合；延迟导入只是启动优化，实际轻量构建还要排除依赖与 PyInstaller 收集项。
- 首发图文报告保留需要的 OpenCV/图像处理能力。三个 OpenCV 分发包先核对 API 使用，再只保留一个合适的 headless 包。
- moviepy 仍被旧 ASR 实现引用；camel-ai 被当前 LLM/VLM 链使用。先核对可达调用与传递依赖，再决定替换，不通过直接删依赖碰运气。
- 章节匹配先验证现有字符串策略；以人工标注样本检查章节顺序、文本覆盖、截图归属。若质量退化不可接受，再比较远程 embedding 或 ONNX，不能只为减包牺牲图文报告准确性。
- 本地增强阶段先验证独立依赖清单构建的增强包。只有需要在应用内安装增强能力时，才建设版本兼容的独立引擎包；不在冻结应用内直接 pip 安装 torch。

### 5.2 下载器作为完整运行能力交付

FFmpeg / FFprobe 使用统一解析器：经校验的已安装组件 → 捆绑资源 → 开发模式 PATH → 明确错误。覆盖 ASR 提取音频、视频切片、抽帧、视频号校验与 yt-dlp 的 `ffmpeg_location`，不能只替换两个文件里的字符串。

YouTube 的 JS runtime 和 EJS 必须一并列入构建与自检。建议先验证捆绑 Deno 的路线，明确绝对路径与版本；是否需要 PO Token 由实际场景决定，不默认要求用户另装服务。EJS 与 yt-dlp 有版本配套关系，官方文档也区分了 Python 包与官方可执行文件的资源包含方式。[yt-dlp EJS 文档](https://github.com/yt-dlp/yt-dlp/wiki/EJS)

首发使用固定且经过样例验证的下载组件，提供版本和诊断信息，通过应用版本更新修复。后续独立更新必须先把搜索、元数据、字幕和下载统一到适配器，再实现组件清单、来源校验、版本配套、原子切换及回退。不能只更新 exe 却继续调用冻结的 `YoutubeDL` 模块，也不能把站点风控、Cookie 失效都归因于版本旧。

### 5.3 优先优化实际耗时与资料体验

- 利用现有 `timing_report.json` 分析下载、ASR、章节匹配、视频处理、VLM 与 LLM 耗时，按样例区分网络等待和本地计算。
- 大文件导入避免整文件内存加载；抽帧和中间片段记录磁盘占用，只有确认未被报告引用的缓存才允许清理。
- 首屏按页面拆分加载，编辑器、Mermaid 与重型渲染组件按需引入；在构建体积和实际加载时间有基线后再调整依赖。
- 统一文档索引，纳入字幕速记和 CLI 产物，避免每次搜索同步扫描并读取所有输出。先支持分页与标题/文本检索；规模需要时再优化全文索引，不先引入向量数据库。
- 编辑器增加自动草稿、保存中/已保存/失败状态、冲突或版本检查、离开保护；验证中文输入法、长文、图片相对路径和快捷键。现有 mock AI 重写不作为可用能力发布。
- 导出采用原生另存为，保留 Web 下载后备；验证大文件不会导致界面长时间无响应。已生成图表的渲染库本地化，并为旧 CDN 文档提供兼容处理，不能只修新产物。

## 6. 桌面壳、平台与发行决策

### 6.1 壳选择用验证结果决定

pywebview 作为当前默认验证方案，目标是低成本复用 Python 团队能力。验证通过即可继续发行，不为“正式版”三个字重写壳。需要替换时，Tauri 2 是候选，Electron 仅在具体 WebView 兼容问题或团队维护优势成立时采用。

pywebview 官方冻结指南目前分别给出 macOS py2app、Windows/Linux PyInstaller 的路径；因此“所有平台同一份 PyInstaller 配置直接打壳”不能作为已验证结论。后端 onedir 与外层壳可用不同工具，若在 macOS 也选 PyInstaller，必须提交真实打包证据。[pywebview 打包指南](https://pywebview.flowrl.com/guide/freezing.html)

Tauri 支持 Python sidecar，但需要按目标架构组织外部二进制；还要完整携带 onedir 的依赖目录，不能只复制一个 exe。切换后需重新验证原生桥、origin、文件读写、退出和签名流程。[Tauri sidecar 文档](https://v2.tauri.app/develop/sidecar/)

### 6.2 第一批桌面验证必须覆盖的行为

- macOS arm64 与 Windows x64 各自产出可运行样包；不在单平台成功后才发现另一平台的打包约束。macOS Intel、Windows ARM 后续按需求扩展。
- 单实例、实际端口握手、启动失败可诊断、后台异常退出可恢复；不根据系统上任意相同进程名进行清理。
- 原生文件选择、中文/空格路径、拖放、另存为、打开目录；平台播放器受限时可转系统浏览器，不能因此阻塞处理。
- 关窗隐藏、继续运行和完全退出行为明确；运行任务和未保存编辑都参与退出协调。首发提供最小菜单，托盘行为仅在各平台验证后启用。
- 睡眠/唤醒、网络切换与服务崩溃不让 UI 永久卡住，也不无限自动重启失败 worker。
- 从 Finder / 开始菜单启动时没有开发者 shell 的 PATH；目标机器无需自行安装 Python、uv、FFmpeg 或 JS runtime。Windows WebView2 的安装/检测方案计入发行验证。

### 6.3 分发与升级

开发样包可在受控测试环境验证；对外发行前分别完成 macOS 签名/公证、Windows 发布者签名与安装升级验证。签名不保证没有 SmartScreen 提示、杀软误报或防火墙行为差异，这些只能按实际测试环境记录。不要把 `xattr -cr` 等关闭隔离方式当作正常用户安装流程。

构建产物只从明确资源清单收集，不把工作区 `settings.json`、Cookies、任务、输出、模型缓存、测试视频或个人绝对路径装入安装包。API Key / Cookie 的系统凭据库接入放在对外发行前，设置界面只显示脱敏状态，诊断导出也要脱敏。

首发通过完整安装包升级，备份并迁移数据结构，保留用户资料；程序回退还要考虑数据 schema 兼容性。后续自动更新将壳、前端和后端作为兼容版本发布，任务执行时不替换正在使用的组件。若选 Tauri updater，更新签名校验是单独的要求，不能与 OS 代码签名混为一谈。[Tauri 更新文档](https://v2.tauri.app/plugin/updater/)
